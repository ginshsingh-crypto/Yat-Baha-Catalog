# Offline browser preview

The GitHub Pages preview includes an Arabic web app manifest and a service worker generated by `scripts/preview.mjs`. This is an optional convenience for reviewing the local preview. It is not a store build, push-notification service, background sync, or a shared backend.

Open the preview while connected and let the first download finish. Reload or reopen it once after the browser reports offline readiness. A supported browser can then reopen the app, navigate report routes, and use local reporting, saved searches, and drafts while offline. The browser may offer **Add to Home Screen** or **Install**; exact behavior depends on the browser and platform. Native Android/iOS installation and physical-device offline behavior have not been verified.

Local report data and photos continue to use the existing device-local storage. They are not uploaded or included in the service-worker cache. Browser storage limits, private browsing, user-cleared site data, and storage eviction can remove offline availability or local reports. Initial download, app updates, and restoring evicted resources need a connection.

## Build and scope

- `pnpm preview:pages` generates a manifest, original-logo icons, registration script, and worker scoped to `/Yat-Baha-Catalog/` (or the configured GitHub repository name).
- `pnpm preview:build` generates the same preview files scoped to `/` for a dedicated preview origin.
- These files are added only by the explicit preview exporter. Standard production Expo builds do not receive a service worker.
- The SVG icon is a square wrapper around the original PNG, preserving its bytes and aspect ratio. It is not a replacement brand design. The original PNG is also used for the Apple touch-icon link.

## Cache behavior

Each build receives a generation hash and a cache prefix derived from its scope. The worker downloads every exported app script, lazy route chunk, font, image, manifest, and registration script before installation succeeds. Every response must be successful and match the exported file's SHA-256 hash. Missing files, HTML fallbacks in place of scripts, corrupt bytes, or cache-write errors abort the new install; the previous build remains available.

Only the known static resource allow-list is served from cache. API paths, other origins, unrelated paths, requests with authorization or Range headers, non-GET requests, and query-bearing asset requests bypass the worker. No runtime response, user request, uploaded photo, account data, or API response is added to cache.

Navigations first try the network for the current generation's HTML. Offline navigation, GitHub Pages dynamic-route 404s, or a slow connection fall back to that generation's precached app shell. A newly deployed HTML shell is held back while an older worker controls the page, preventing a shell from referencing unprepared chunks. The newer worker prepares its own complete generation separately.

Updates do not call `skipWaiting()` or `clients.claim()`. They wait until the old preview tabs/windows close, then activate when the app is reopened. This avoids forcing a reload during report entry. Activation removes only older caches bearing this exact app-and-scope prefix; it never clears local storage, drafts, report data, another app's cache, or another repository's scope.

The registration script exposes `document.documentElement.dataset.previewOffline` and dispatches `yat-preview-offline` with `{ state: 'ready' | 'update' | 'unavailable' }`. `ready` means the generation completed its cache install; on the first visit the page still needs to be reopened to become controlled. `update` means close all preview tabs/windows and reopen when convenient.

## Verification

Run:

```sh
node --test scripts/preview-offline.test.mjs
pnpm preview:pages
PREVIEW_EXPORT_DIR=artifacts/yat-biha/dist node --test scripts/preview-offline.test.mjs
```

The tests exercise both root and repository scopes, preservation of the original image bytes, generated resource paths, complete-cache installation, offline deep routes, encoded lazy chunk paths, current-generation network navigation, new-generation isolation, API/remote/mutation exclusions, scoped old-cache cleanup, and failed/mismatched precache installation. When `PREVIEW_EXPORT_DIR` is provided, the actual generated manifest, HTML references, precache hashes, and resource sizes are also checked.

These are generated-output and service-worker runtime tests in an isolated JavaScript harness. They do not establish browser installation support or real iPhone/Android offline operation. Test those on the intended devices before promising offline behavior to public users.

Reference: [MDN service worker lifecycle and caching](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).
